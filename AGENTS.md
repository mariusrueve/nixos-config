# Agent guide for this NixOS configuration

This repo is the complete NixOS system config for Marius' desktop (hostname `desktop`).
`/etc/nixos` is a symlink to this directory. AI agents (Claude Code etc.) are used
here to help troubleshoot and evolve the config.

## Layout

| File | Purpose |
|------|---------|
| `flake.nix` | Entry point. Inputs: `nixpkgs` (nixos-26.05), `home-manager` (release-26.05), `claude-code-nix` (overlay providing an up-to-date `pkgs.claude-code`), `catppuccin` (catppuccin/nix release-26.05, theming modules for NixOS + Home Manager). Defines `nixosConfigurations.desktop`. |
| `flake.lock` | Exact pinned revisions of all inputs. Only changes via `nix flake update`. |
| `configuration.nix` | Core system config (boot, fs, nix, locale, audio, NVIDIA, users, sudo rule). Imports `modules/` and sets `home-manager.users.marius = import ./home`. |
| `modules/desktop.nix` | System side of the Hyprland desktop: Hyprland (UWSM), greetd + tuigreet, portals, gnome-keyring, NVIDIA udev symlink, Bluetooth/gvfs/udisks, fonts, kept GNOME apps. |
| `modules/snapshots.nix` | snapper: hourly btrfs snapshots of `/home` (24 hourly / 7 daily / 4 weekly) into the `/home/.snapshots` subvolume; btrfs-assistant GUI. Same disk, so not a backup against disk failure. |
| `home/default.nix` | Home Manager entry: shell, editors, git/gh, direnv, tmux; imports the files below. |
| `home/hyprland.nix` + `home/hyprland.lua` | Hyprland user config. Hyprland 0.55 uses a **Lua** config; `hyprland.lua` holds monitors, look, keybinds and rules and is appended to the generated `~/.config/hypr/hyprland.lua`. Session env vars go to `~/.config/uwsm/env*`, not into the Lua. |
| `home/waybar.nix` | Waybar layout + CSS. |
| `home/services.nix` | hyprpaper, hyprlock, hypridle, hyprsunset (night light), swaync, swayosd, cliphist, polkit agent, udiskie. The nm-applet/blueman tray applets come from system XDG autostart; don't also enable their Home Manager services (duplicates). |
| `home/apps.nix` | kitty, rofi, wlogout. |
| `home/theme.nix` | Catppuccin Mocha/blue, cursors, GTK/Qt, icons. |
| `wallpapers/` | Wallpaper used by hyprpaper and hyprlock. |
| `hardware-configuration.nix` | Generated by `nixos-generate-config`. Do not hand-edit unless the hardware/disk layout changed. |

No channels are used for the system build; everything comes from `flake.lock`.

## Privileges: the agent runs without root

Agents run as the unprivileged user `marius`. `sudo` requires a password, and agents
do not have it, with **one deliberate exception**: `configuration.nix` contains a
`security.sudo.extraRules` entry allowing

```
sudo /run/current-system/sw/bin/nixos-rebuild ...
```

without a password. Why: so an agent can apply a fix and verify it end-to-end in one
step, instead of stopping and asking Marius to type his password for every rebuild.

Be aware this is a trust grant, not a sandbox: `nixos-rebuild` activates whatever
configuration it is given and runs as root, so it can technically be used to gain full
root. The owner has accepted that risk. In return, agents must follow these rules:

- Only ever rebuild **this** repo's flake (`/etc/nixos`, i.e. this directory). Never
  pass `-I`, `--flake <other path>`, `--option`, `--override-input`, or anything that
  points `nixos-rebuild` at code from elsewhere.
- Never use `nixos-rebuild` as a workaround to obtain root for an unrelated task
  (reading root-owned files, changing permissions, running commands as root, ...). If
  something genuinely needs root, tell Marius and let him run it with `! sudo ...`.
- Do not modify or remove the sudo rule itself without being asked.
- Do not run `nix flake update` (bumping pinned inputs) unless asked; it changes far
  more than a targeted fix.

## Workflow for changes

1. Edit the `.nix` files.
2. **`git add` new files.** Flakes only see files tracked by git; an untracked file is
   invisible and produces confusing "file not found" / "path does not exist" errors.
   (Committing is not required, staging is enough.)
3. Validate without touching the running system (no sudo needed):
   ```sh
   nixos-rebuild build --flake .            # builds ./result, no activation
   nix store diff-closures /run/current-system ./result   # what would change
   ```
   For quick evaluation checks:
   ```sh
   nix eval .#nixosConfigurations.desktop.config.<option.path>
   ```
4. Activate:
   - `sudo nixos-rebuild test` activates without making it the boot default
     (a reboot reverts). Prefer this for risky changes (graphics, display manager,
     boot, networking).
   - `sudo nixos-rebuild switch` activates and makes it the boot default.
   Tell Marius before switching anything that can kill the graphical session
   (greetd/Hyprland/NVIDIA changes). Restarting greetd ends the running session.
5. Commit only when Marius asks.

Rollback if something breaks: `sudo nixos-rebuild switch --rollback`, or pick an older
generation in the systemd-boot menu.

## Troubleshooting tips

- Show the full error trace: add `--show-trace` to `nixos-rebuild` / `nix eval`.
- Logs: `journalctl -b -p warning`, `journalctl -u <unit>`, `journalctl --user -u <unit>`.
  Home Manager activation: `journalctl -u home-manager-marius`.
- Option docs: `man configuration.nix`, `man home-configuration.nix`, or
  https://search.nixos.org/options.
- `pkgs.claude-code` comes from the `claude-code-nix` overlay, **not** nixpkgs. To get a
  newer Claude Code: `nix flake update claude-code-nix` (only when asked).
- `home-manager.useGlobalPkgs = true`: Home Manager uses the system `pkgs` (including
  overlays and `allowUnfree`); do not set `nixpkgs.*` inside the Home Manager block.
- Do not change `system.stateVersion` or `home.stateVersion`.
- GPU: NVIDIA RTX 4070 (PCI 01:00.0, drives the only monitor, DP-4) plus an AMD iGPU
  (PCI 10:00.0). Hyprland is pinned to the NVIDIA card via
  `AQ_DRM_DEVICES=/dev/dri/nvidia-gpu` (udev symlink in `modules/desktop.nix`).
- Desktop: Hyprland via UWSM, started from greetd/tuigreet. Validate Hyprland config
  changes without a session: build, then
  `XDG_CONFIG_HOME=<dir containing hypr/ with symlinks to the built files> Hyprland --verify-config`
  (using `-c <store path>` breaks the `require('themes.catppuccin')` lookup).
  Inside a session: `hyprctl reload`, `hyprctl configerrors`.
- Desktop user services: `systemctl --user status waybar swaync hypridle hyprpaper ...`.
- Git and gh are managed by Home Manager (`programs.git`, `programs.gh` with
  `gitCredentialHelper`). Do not run `gh auth setup-git`: it writes a hardcoded
  `/nix/store/...` path into `~/.gitconfig`, which breaks after garbage collection.
  `~/.gitconfig` holds only the user identity.
- Prebuilt non-Nix binaries work via `programs.nix-ld`. For per-project toolchains,
  prefer a flake `devShell` + `.envrc` with `use flake` (direnv + nix-direnv are set
  up) over adding packages system-wide.
