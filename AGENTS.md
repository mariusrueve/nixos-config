# Agent guide for this Nix configuration

This repo configures Marius' machines from one flake:

- **`desktop`**: NixOS + Hyprland (x86_64-linux, NVIDIA). `/etc/nixos` is a symlink to this directory.
- **`macbook`**: macOS via nix-darwin (aarch64-darwin, Apple Silicon), cloned to `~/nixos-config`.
- **`hessen`** (user `mrueve`): university compute server (openSUSE, x86_64-linux), **no root**. Standalone
  Home Manager only (`homeConfigurations."mrueve@hessen"`), cloned to `/local/mrueve/nixos-config`. See "hessen" below.

All of them run the same Home Manager modules (`home/common/`): shell, Neovim, git and CLI tools (kitty on the desktop and Mac only).
So the terminal workflow is identical, and only the window manager layer differs (Hyprland vs. AeroSpace,
with matching keybinds). AI agents (Claude Code etc.) are used here to help troubleshoot and evolve the config.

Check which host you are on (`uname -s`: Darwin = macbook; Linux = desktop, or hessen if `hostname -s` says so) before
building or activating anything.

## Layout

| Path | Purpose |
|------|---------|
| `flake.nix` | Entry point. Inputs: `nixpkgs` (nixos-26.05), `nixpkgs-darwin` (nixpkgs-26.05-darwin, for the Mac), `home-manager` (release-26.05), `nix-darwin` (nix-darwin-26.05), `claude-code-nix` (overlay providing an up-to-date `pkgs.claude-code`), `codex-cli-nix` (same for `pkgs.codex`), `catppuccin` (catppuccin/nix release-26.05), `nixvim` (nixos-26.05). Outputs: `nixosConfigurations.desktop`, `darwinConfigurations.macbook`, `homeConfigurations."mrueve@hessen"`, `templates.{python,rust,latex}`. The `shared` module there sets overlays, `allowUnfree` and the Home Manager plumbing (`useGlobalPkgs`, `sharedModules` = catppuccin + nixvim) for both hosts. |
| `flake.lock` | Exact pinned revisions of all inputs. Only changes via `nix flake update`. |
| `hosts/desktop/configuration.nix` | Desktop system config (boot, fs, nix, locale, audio, NVIDIA, users, sudo rule). Imports `modules/` and sets `home-manager.users.marius = import ../../home/desktop.nix`. |
| `hosts/desktop/hardware-configuration.nix` | Generated by `nixos-generate-config`. Do not hand-edit unless the hardware/disk layout changed. |
| `hosts/macbook/default.nix` | nix-darwin config: user/shell, weekly GC launchd job, Touch ID sudo, `system.defaults` (Dock, Finder, key repeat), fonts, JankyBorders, **`homebrew.casks` (Mac GUI apps)**. `nix.enable = false`: Nix itself is managed by the Determinate installer. | `modules/desktop.nix` | (NixOS) System side of the Hyprland desktop: Hyprland (UWSM), greetd + tuigreet, portals, gnome-keyring, NVIDIA udev symlink, Bluetooth/gvfs/udisks, fonts, kept GNOME apps. |
| `modules/snapshots.nix` | (NixOS) snapper: hourly btrfs snapshots of `/home` (24 hourly / 7 daily / 4 weekly) into the `/home/.snapshots` subvolume; btrfs-assistant GUI. Same disk, so not a backup against disk failure. |
| `home/desktop.nix`, `home/macbook.nix` | Per-host Home Manager entry points: `common` + `common/kitty.nix` + `linux` or `darwin`. |

| `home/common/kitty.nix` | kitty (shared; a few `isDarwin` tweaks). On macOS `package = null`: the app is the Homebrew cask, because nixpkgs' wrapped `kitty.app` registers with LaunchServices without a PID and AeroSpace never tiles it. Keep it that way; Option+Enter opens `/Applications/kitty.app` by full path. |
| `home/common/neovim/` | The editor: Neovim via **nixvim** (`programs.nixvim`), `$EDITOR`. `default.nix` (options, keymaps, cheat sheet, catppuccin), `ui.nix`, `lsp.nix` (servers, blink-cmp, treesitter, conform format-on-save), `languages.nix` (vimtex with zathura on Linux / Skim on macOS, rustaceanvim, markdown), `dap.nix` (debugpy, codelldb). | `home/darwin/default.nix` | macOS-only `home.packages`. |

| `templates/` | Per-project dev shells (`nix flake init -t ~/nixos-config#python` / `#rust` / `#latex`, then `direnv allow`). No channels are used; everything comes from `flake.lock`.

Where to put a new program:
- **CLI, both machines:** `home/common/default.nix`.
- **Linux GUI app:** `home/linux/default.nix`.
- **Mac GUI app:** a Homebrew cask in `hosts/macbook/default.nix`.
- **Project-specific toolchain:** the project's own flake, from a template.

## Privileges: the agent runs without root

Agents run as the unprivileged user `marius`. `sudo` requires a password, and agents
do not have it, with **one deliberate exception on the desktop only**:
`hosts/desktop/configuration.nix` contains a `security.sudo.extraRules` entry allowing

```
sudo /run/current-system/sw/bin/nixos-rebuild ...
```

without a password. Why: so an agent can apply a fix and verify it end-to-end in one
step, instead of stopping and asking Marius to type his password for every rebuild.
**The MacBook has no such rule.** `sudo darwin-rebuild switch` needs Marius (Touch ID), so
on the Mac prepare and build the change, then ask him to run the switch with `! sudo darwin-rebuild switch --flake ~/nixos-config`.

Be aware this is a trust grant, not a sandbox: `nixos-rebuild` activates whatever
configuration it is given and runs as root, so it can technically be used to gain full
root. The owner has accepted that risk. In return, agents must follow these rules:

- Only ever rebuild **this** repo's flake (`/etc/nixos`, i.e. this directory). Never
  pass `-I`, `--flake <other path>`, `--option`, `--override-input`, or anything that
  points `nixos-rebuild` at code from elsewhere.
- Never use `nixos-rebuild` as a workaround to obtain root for an unrelated task
  (reading root-owned files, changing permissions, running commands as root, ...). If
  something genuinely needs root, tell Marius and let him run it with `! sudo ...`.
- Do not modify or remove the sudo rule itself without being asked.
- Do not run `nix flake update` (bumping pinned inputs) unless asked; it changes far
  more than a targeted fix.

## Workflow for changes

1. Edit the `.nix` files. A change in `home/common/` affects **both** machines: keep it
   platform-neutral, or guard it with `pkgs.stdenv.isDarwin` / `isLinux`.
2. **`git add` new files.** Flakes only see files tracked by git; an untracked file is
   invisible and produces confusing "file not found" / "path does not exist" errors.
   (Committing is not required, staging is enough.)
3. Validate without touching the running system (no sudo needed):
   ```sh
   # desktop
   nixos-rebuild build --flake .            # builds ./result, no activation
   nix store diff-closures /run/current-system ./result   # what would change
   # macbook
   darwin-rebuild build --flake .
   nix store diff-closures /run/current-system ./result
   ```
   Quick evaluation checks (work from either machine for either host):
   ```sh
   nix eval .#nixosConfigurations.desktop.config.<option.path>
   nix eval .#darwinConfigurations.macbook.config.<option.path>
   nix flake check --no-build
   ```
   The whole Mac system cannot be evaluated from the desktop: the catppuccin starship theme is an
   import-from-derivation that must be built on aarch64-darwin. Evaluating individual options works.
4. Activate:
   - **Desktop:**
     - `sudo nixos-rebuild test` activates without making it the boot default (a reboot reverts).
       Prefer this for risky changes (graphics, display manager, boot, networking).
     - `sudo nixos-rebuild switch` activates and makes it the boot default.
     - Tell Marius before switching anything that can kill the graphical session
       (greetd/Hyprland/NVIDIA changes). Restarting greetd ends the running session.
   - **MacBook:** Marius runs `sudo darwin-rebuild switch --flake ~/nixos-config` (see above).
5. Commit only when Marius asks. After a change on one machine, the other picks it up with `git pull` plus a rebuild.

Rollback if something breaks:
- **Desktop:** `sudo nixos-rebuild switch --rollback`, or pick an older generation in the systemd-boot menu.
- **Mac:** `sudo darwin-rebuild switch --rollback`.

## First-time MacBook setup

1. On the fresh macOS, create the user `marius` and run `xcode-select --install`.
2. Install Nix with the Determinate Systems installer (flakes enabled).
3. Install Homebrew (https://brew.sh).
4. Run `git clone <repo> ~/nixos-config`.
5. Run `sudo nix run nix-darwin -- switch --flake ~/nixos-config#macbook`.
6. One-time manual steps:
   - Allow AeroSpace under Privacy & Security → Accessibility.
   - Set Raycast's hotkey to Cmd+Space after disabling Spotlight's shortcut (Keyboard → Shortcuts).
   - Make Chrome the default browser.
   - Under Lock Screen, set "require password after screen saver/display off" to "Immediately" (Option+Esc locks by turning off the display).

## hessen (uni server, no root)

Login: Mac or desktop → `ssh hessen` (via `bari.zbh.uni-hamburg.de:7373`). Keys in 1Password; the public key is in the NFS
`~/.ssh/authorized_keys` and in Gerrit. The forwarded agent signs `git push` to Gerrit.

- **No sudo, no Nix daemon.** `/local/mrueve/bin/nix-user-chroot` mounts `/local/mrueve/nix` as `/nix` in an
  unprivileged user namespace and runs a single-user Nix inside it. The rest of `/` stays visible (`/work`, `/scratch`, `/data`,
  `/usr/local/zbhtools`, SGE).
- **Two homes.** `/home/stud2022/mrueve` is NFS and shared with bari and every node, so it must never contain `/nix/store`
  links. Its `~/.bashrc` is only a hook (written by `bootstrap.sh`, not by Home Manager) that `exec`s into the chroot for
  interactive shells on hessen, with `HOME=/local/mrueve/home`. Home Manager owns that directory. The old dotfiles are
  in `~/pre-nix-backup/`. Escape hatch: `touch /local/mrueve/.nonix` and reconnect. `~/.ssh` is still read from the NFS home.
- **Setup:** `scp hosts/hessen/bootstrap.sh hessen:/local/mrueve/ && ssh hessen bash /local/mrueve/bootstrap.sh`.
- **Update** (inside the env): `cd /local/mrueve/nixos-config && git pull && home-manager switch --flake .#mrueve@hessen`.
  Changes have to be pushed to GitHub first. Building and testing from the desktop (same arch) works too:
  `nix build .#homeConfigurations."mrueve@hessen".activationPackage`. From the Mac only options without the starship IFD evaluate.
- **SGE jobs run on other nodes, which have no `/nix`.** Nix is for interactive development only.
  - Job environments are uv venvs on `/work` or `/scratch`, built from a uv-managed Python (`UV_PYTHON_INSTALL_DIR=/work/stud2022/mrueve/opt/uv-python`).
  - Job scripts `source .venv/bin/activate`.
  - Don't `qsub -V` from the Nix shell, because PATH would point into `/nix/store`.
  - `/local` is per node: jobs must use `/work` or `/scratch`.
- **Pitfalls found during setup:**
  - The login session (PAM) exports `XDG_CONFIG_HOME` etc. pointing at the NFS home. `xdg.enable` in `home/hessen.nix` exports them again inside the env.
    Without it, git, nvim and even `nix.conf` are not found.
  - hessen's AppArmor profile only lets `/usr/bin/curl -o` write to `/tmp`. Use `curl … > file` instead.
- `.space` files (SQLite) are slow over NFS, so work happens in `/local/mrueve/home` (`phd/`, `knowledge/`, `notes/`).
  - Backup: `hosts/hessen/backup.sh`, deployed as `/local/mrueve/scripts/hessen-backup.sh` (cron 02:30).
    It writes daily rsync snapshots with hardlinks to the previous day, keeps 7, and goes to `/work/stud2022/mrueve/backups/hessen` (with `backup.log`).
  - Excluded: `.cache` and Nix state. The store is rebuilt from this repo.
  - Deploy after changes: `scp hosts/hessen/backup.sh hessen:/local/mrueve/scripts/hessen-backup.sh`.

## Troubleshooting tips

- Show the full error trace: add `--show-trace` to `nixos-rebuild` / `darwin-rebuild` / `nix eval`.
- **Desktop logs:**
  - `journalctl -b -p warning`, `journalctl -u <unit>`, `journalctl --user -u <unit>`.
  - Home Manager activation: `journalctl -u home-manager-marius`.
- **Mac logs:**
  - `launchctl list | grep -E 'aerospace|borders'`.
  - AeroSpace log: `/tmp/aerospace.err.log`.
  - Reload the AeroSpace config: `aerospace reload-config`.
- Option docs: `man configuration.nix`, `man darwin-configuration.nix`,
  `man home-configuration.nix`, https://search.nixos.org/options,
  https://nix-darwin.github.io/nix-darwin/manual/.
- `pkgs.claude-code` comes from the `claude-code-nix` overlay, **not** nixpkgs. To get a
  newer Claude Code: `nix flake update claude-code-nix` (only when asked). Likewise
  `pkgs.codex` comes from `codex-cli-nix` (`nix flake update codex-cli-nix`).
- `home-manager.useGlobalPkgs = true`: Home Manager uses the system `pkgs` (including
  overlays and `allowUnfree`); do not set `nixpkgs.*` inside the Home Manager block.
- Do not change `system.stateVersion` (either host) or `home.stateVersion`.
- GPU: NVIDIA RTX 4070 (PCI 01:00.0, drives the only monitor, DP-4) plus an AMD iGPU
  (PCI 10:00.0). Hyprland is pinned to the NVIDIA card via
  `AQ_DRM_DEVICES=/dev/dri/nvidia-gpu` (udev symlink in `modules/desktop.nix`).
- **Hyprland** runs via UWSM, started from greetd/tuigreet.
  - To validate a config change without a session, build, then run
    `XDG_CONFIG_HOME=<dir containing hypr/ with symlinks to the built files> Hyprland --verify-config`.
    Don't use `-c <store path>`: it breaks the `require('themes.catppuccin')` lookup.
  - Inside a session: `hyprctl reload`, `hyprctl configerrors`.
- Desktop user services: `systemctl --user status waybar swaync hypridle hyprpaper ...`.
- Git and gh are managed by Home Manager (`programs.git`, `programs.gh` with
  `gitCredentialHelper`). Do not run `gh auth setup-git`: it writes a hardcoded
  `/nix/store/...` path into `~/.gitconfig`, which breaks after garbage collection.
  The user identity (name + GitHub noreply email) is set in `programs.git.settings.user`; keep `~/.gitconfig` absent so it cannot override it.
- Prebuilt non-Nix binaries work via `programs.nix-ld` (desktop). For per-project
  toolchains, prefer a flake `devShell` from `templates/` + `.envrc` with `use flake`
  (direnv + nix-direnv are set up on both machines) over adding packages globally.
